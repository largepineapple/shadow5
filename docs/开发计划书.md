# 素材制作网站开发计划书

日期：2026-10-29；交付仓库：https://github.com/largepineapple/shadow5

## 1. 目标与验收原则

以完整满足 R-01～R-14、争取 90 分以上为目标。题目没有公开分项权重，因此不虚构评分，也不承诺实际分数。以需求追踪表、关键行为测试、容器实跑和诚实交付记录形成可核验的证据。

当前阶段仅制定计划，不表示功能已实现。当前目录只有 Git 元数据；网络暂无法访问 GitHub 和题目四张图片。正式开发前须读取远端已有内容、检查仓库规则，并获取参考图核对布局，避免覆盖已有作业。以下视觉设计暂依据文字要求。

## 2. 最小完整架构

- 前端：Next.js App Router、React、TypeScript；模板列表、详情制作、个人历史三个主要页面。CSS 完成响应式布局，TanStack Query 管理服务端数据及轮询，Vitest/Testing Library 验证异步状态。
- 后端：Java 21、Spring Boot 3.5.x、MyBatis Spring Boot Starter 3.0.x、Maven Wrapper；业务、文件校验、身份隔离、任务执行及持久化全部由 Java 负责。
- 数据库：MySQL 8.4，Flyway 管理结构和种子数据。前端采用 Next.js 16.x、React 19.x 的兼容组合，启动实施时核对官方兼容信息并锁定精确补丁版本和 lockfile；CI、Docker、README 使用同一版本。
- 运行：Compose 启动 web、api、mysql；数据库健康检查和后端就绪检查决定启动顺序。浏览器通过同源 /api 代理至 Java，容器内使用 api:8080 和 mysql:3306。
- 文件：后端数据卷保存上传图片与结果；仓库自带合法本地封面及示例结果，记录素材来源。结果整理阶段复制预置结果为任务专属文件并保存地址。
- 执行：单个 Java 后台工作线程定时领取 MySQL 中 QUEUED 任务，顺序执行三阶段；提交只检查参数并提交数据库事务，不执行耗时步骤。数据库队列避免线程池拒绝导致任务丢失，不引入 Redis 或消息队列。

## 3. 数据、身份与接口

核心表：users（匿名身份及令牌摘要）、templates（分类、封面、图片要求）、assets（所属用户、真实 MIME、大小、存储路径）、tasks（用户、模板、状态、当前阶段、失败阶段、原因、结果、模拟参数快照、时间）、task_assets（有序素材关联）、task_steps（每阶段开始/结束、状态和原因）。所有业务查询限定 user_id。

匿名会话：首次访问由 Java 创建匿名用户，设置 HttpOnly、SameSite Cookie，HTTPS 环境启用 Secure；数据库仅保存令牌摘要。刷新保留身份；无 Cookie 的独立浏览器代表另一用户。明确匿名身份不支持跨设备找回。生产写接口限制 Origin；开发身份切换功能仅开发配置可用，切换时取消请求并清理缓存。图片预览通过 Java 校验所有权后返回，不暴露磁盘路径。

拟定接口：

| 接口 | 主要输入/输出 |
| --- | --- |
| POST /api/session | 创建或恢复匿名会话，返回当前用户展示信息 |
| GET /api/templates?category= | 分类与模板摘要 |
| GET /api/templates/{id} | 描述、封面、requiredImageCount、acceptedMimeTypes、maxFileSizeBytes |
| POST /api/assets | multipart 图片，返回 assetId、previewUrl、mimeType、sizeBytes |
| POST /api/tasks | templateId、按上传位排序的 assetIds；返回 202 和 taskId、status、stage |
| GET /api/tasks/{id} | 状态、阶段、步骤时间、失败原因、resultUrl |
| GET /api/tasks?cursor=&limit= | 当前用户历史任务、创建时间、分页游标 |
| GET /api/assets/{id}/content | 鉴权后返回上传文件或任务结果 |

统一错误体 code、message、fieldErrors、requestId；明确 400/401/404/413/415 等错误。创建任务校验模板存在、数量精确、素材归属、素材已落盘且符合模板要求。上传同时检查大小、扩展名之外的真实文件内容和图片可解码性，限制像素数量，使用随机存储名防止路径穿越，不信任客户端 MIME。

## 4. 异步状态与关键不变量

整体状态：QUEUED → RUNNING → SUCCEEDED 或 FAILED；阶段：ASSET_CHECK → GENERATE → FINALIZE。等待时 stage 为空；每阶段开始先持久化边界，再执行延迟/模拟操作，完成后保存步骤结果。三个阶段分别实现，查询接口仅查询数据库。工作线程只领取等待任务，终态不可重新执行或被查询改变。

不跨模拟等待持有数据库事务。任何阶段异常立即记录 FAILED、failedStage 和可理解原因，停止后续步骤；避免向用户返回堆栈。只有结果文件存在且结果记录提交成功，任务才成功。

开发配置提供各阶段 delayMs，以及指定阶段 failAt；创建任务时保存快照，确保重复演示结果可预测。控制参数仅在 demo profile 下的开发接口接受，生产配置禁用；校验阶段枚举和延迟上限。至少演示三个阶段分别失败。

重启边界：等待任务仍可被领取；进程重启时将遗留 RUNNING 任务明确标为失败并说明服务中断，不声称支持断点续跑。单实例执行是已知限制，不扩展集群抢占或自动重试。

## 5. 前端交互与视觉

列表具有分类导航、封面卡片和清晰入口；详情显示大封面、要求、对应数量上传位及制作按钮；历史按时间展示任务卡片、阶段和结果预览。读取参考图后对齐主要布局。桌面为主，小屏单列可操作，保留焦点、语义按钮、图片标签和状态播报。

上传位独立管理 selected/uploading/ready/error，支持选择、预览、替换、移除和失败重试。替换时取消旧上传或用请求序号丢弃迟到响应；移除时释放 object URL。浏览器地址只用于本地即时预览，提交使用后端 assetId。

提交中禁用按钮；受理成功立即显示新任务并恢复创建其他任务能力。每个任务使用包含 userId 和 taskId 的独立查询键，轮询未完成任务（建议 2 秒）；终态停止、页面卸载取消、用户切换取消并清空缓存。没有待处理任务时无任务轮询。

查询网络异常保留已有任务状态，显示“状态暂时无法更新”及恢复查询入口，绝不将其改成业务 FAILED。刷新先加载个人历史，再对未完成任务恢复跟踪。列表/详情具有加载、空态、404、失败重试反馈。

## 7. 测试与 CI 方案

后端 JUnit 验证阶段顺序、指定阶段失败中断、异常保存、终态不回退；使用可替换时钟/等待器减少真实睡眠。Testcontainers MySQL 验证真实 Mapper、迁移、用户隔离、素材校验及任务提交/领取，避免只用 H2 掩盖数据库差异。

前端 Vitest、Testing Library 和 MSW 模拟两个任务不同进度、乱序响应、请求异常后恢复、业务失败、刷新恢复、轮询停止和卸载取消。测试用户可观察行为，避免仅断言内部实现。

GitHub Actions 分前后端两个作业：npm ci → lint → tsc --noEmit → test → build；Maven Wrapper verify（包含测试与打包）。CI 不跳过测试，不用真实凭据。容器交付再做一次清洁环境冒烟；保存命令、结果和失败修复记录。没有运行的检查明确标注未验证。

## 9. 交付门禁与范围取舍

提交前逐条核对 R-01～R-14；阻断交付的问题包括：后台靠前端推进、查询触发状态变化、刷新丢失、跨用户访问、终态回退、查询异常被标记任务失败、CI 构建失败、容器无本地素材。发现后先修复，再确定验收提交。

README 包含版本、目录、配置示例、启动/构建/测试命令、数据库初始化、接口字段、状态机、模拟成功与三阶段失败、耗时控制、多任务和刷新、身份、实际投入和取舍、已完成/未完成、素材来源及 AI 工作流。AI 工作流如实记录需求拆解、上下文、代码修改、测试验证和具体问题修正，不提交私人记录。

提供 .env.example、Dockerfile、compose.yaml、健康检查、持久化卷、数据库迁移和演示脚本。部署步骤为备份数据库/文件卷、拉取指定 commit、构建启动、健康检查和冒烟；回滚到上一镜像/commit，数据库采用前向兼容迁移，涉及不兼容结构时先维护停机并恢复备份；不使用删除卷作为常规回滚。

明确不做真实 AI、支付、会员、模板后台、第三方登录、Redis/MQ、集群、断点续跑、自动重试。受理幂等与孤立文件清理只讨论限制；不为扩展牺牲必需功能。

交付时推送到指定仓库并提供完整 commit SHA、仓库链接、运行和测试记录；无法推送时保留本地源码及明确网络阻塞，不宣称上传成功。
